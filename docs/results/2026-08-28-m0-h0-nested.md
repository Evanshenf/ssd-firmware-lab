- kernel `checkpatch.pl --strict`: zero errors, warnings or checks;

`fffa` was absent from the pinned environment's current `pci.ids`; it is not assigned to or owned by this project and must not be used for distributed hardware. Binding safety came from setting `driver_override=none` before device publication, not from assuming the ID remains unused.

The in-kernel order was:

```text
allocate emulation-only domain >= 0x10000
→ scan root bus while holding pci_rescan_remove_lock
→ set driver_override=none
→ publish devices
→ inspect
→ stop/remove root bus under the same lock
→ free bridge/domain and root device
```

## Cleanup evidence

- module unloaded normally; no forced removal;
- function BDF, root bus and synthetic root device disappeared;
- bus-number resource was released;
- no new BUG, WARNING, Oops, KASAN, lockdep or protection fault appeared;
- only expected out-of-tree and unsigned-module taint bits were added (`12288`);
- a normal reboot restored taint to zero;
- private media was still read-only, unmounted and unmodified after reboot.

## What this proves

Ubuntu GA 7.0 exports enough GPL kernel API for an out-of-tree module to create, safely publish and remove an inert synthetic PCI function. A custom kernel is not needed for this H0 sub-gate.

## What remains STOP

This result does not authorize or validate:

- boot-time reserved memory or a BAR;
- PAT/cache-type alias safety;
- IRQ, MSI or MSI-X;
- DMA, SWIOTLB behavior, IOMMU ownership or revocation;
- storage-controller class publication;
- native storage-driver binding;
- bare-metal graduation.

H1 must remain vendor-class and pass reserved-BAR/PAT tests. A separate lab driver must then pass IRQ teardown and per-mapping Host-DMA gates before any native storage-driver bind is considered.

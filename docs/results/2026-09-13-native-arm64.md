Status: native L1 test matrix completed; final publication validation is pending.
This is not a new frozen release, physical
SSD qualification, or a claim that every earlier test ran on the latest hash.

## Exact source boundaries

`50b1e4b` and `b486fa9`. The drain/readiness correction is `c390611`. The subsequent

## Platform and fixes exercised

The selected environment is Ubuntu26.04 ARM64, Linux7.0.0-30-generic
(7.0.0-30.30), 4-KiB pages, eight CPUs and96GiB RAM. Stock GRUB2.14 reserved a
new exact16-KiB EFI Unusable/WB/non-Runtime range, with fresh before/after map
checks; Linux confirmed the reserved NOMAP aperture. Default boot remained
unchanged. See [ADR-0016](../adr/0016-arm64-native-platform.md).

The first native ARM experiment exposed sleeping DMA callbacks in atomic Linux
contexts. Later, a real reset raced worker MSI polling: the worker held the PCI
configuration spinlock while waiting for the MSI descriptor mutex; MSI shutdown
held that mutex and waited for the configuration lock. Both sides were recovered
from actual guest stacks. Linux7 IRQ validation now uses the allocation-owned
virq/generation record, with publish-after-setup and invalidate/synchronize/free
ordering. These are transport fixes, not a new FTL or a bypass of NAND modeling.

Large-media reconstruction also required separating completed drain from new
firmware readiness. The native64GiB shaped episode measured reset6.44s,
unbind0.06s and shutdown status about2.2ms after observed SHN; these are samples,
not universal bounds. CAP.TO provides a fixed60s construction budget. The
distinct drained/unbound FLR case does not close the general N01 publication
window. See [ADR-0017](../adr/0017-large-controller-readiness.md).

## Native 1-MiB performance samples

Each value is the median of three15-second samples. MB/s is decimal. One fio
job used CPU6 and one firmware worker CPU7. The extent was1GiB at [8GiB,9GiB)
inside a64GiB namespace, on the same tmpfs physical-v2 NAND model. One1-MiB
application request was split into eight128-KiB native commands by this Linux
binding. Requested QD32 was attained at the application layer, not by32 parallel
FTL executors.

All26 fio phases exited successfully, all12 timed samples met byte/error/timer
checks, and all six writers received exact1GiB final-state verification. Reads
verified data online. Each timed writer used a distinct B generation after a
separate A prefill; if it completed less than one extent, final reads checked B
only in the completed sequential prefix and A in the suffix. The slow QD32
writer completed853MiB and passed853MiB B +171MiB A checks. It coincided with a
checkpoint and4.144s CLAT p99; this establishes co-occurrence, not independent
causal attribution. All timed GC deltas were zero.

Rates use actual fio runtimes, not an assumed exact15s divisor. Prefills and
postchecks are outside timing; fio buffer/header work, online read verification,
kernel/transport and unchanged firmware CRC/sync/logging remain included. Timed
writers add no periodic host end_fsync, while DUT persistence operations remain
unchanged. These are not10GB/s, whole-device steady-state/GC-pressure, physical
NAND or PCIe4/5 saturation results. They are not a matched regression ratio
against earlier BLOCK-only measurements over a64MiB volume.

## Filesystem integration

One ext4 episode completed in 1,659.699 seconds (27m39.699s). It operated only on
the newly owned synthetic namespace; the NAND backend was not reformatted.
Before bulk fill, a 4-MiB file was synced, renamed and directory-synced, then
verified after native reset/remount and unbind/rebind/remount.

Each bulk file was copied from a separately generated, unique 512-MiB GOLD
payload. Its source hash was recorded outside the tested filesystem only after
successful copy, file fsync and directory fsync. All 124 complete chunks were
retained through actual full-space conditions; a subsequent 4-KiB allocation
also returned ENOSPC. The failed partial tail remains separate and is not claimed
as a successfully synced file. No preallocation-only "full disk" result was used.

After verifying and deleting one known 512-MiB chunk, a new 64-MiB file allocated
and verified successfully. Unmounted `e2fsck -f -n` exited0. After remount, all
125 manifest files matched their source SHA-256 values: 66,106,425,344 bytes in
total. The filesystem was normally unmounted at the end, with no new kernel
warning or filesystem error. The 3-GiB test-process cgroup constrained file-cache
use; no physical SSD performance conclusion follows from this integration run.

The source scratch file stayed within the separate 1-GiB tmpfs limit and ended
at 64 MiB. Discard was disabled explicitly because this profile does not advertise
DSM/TRIM; lazy inode/journal initialization was disabled. This is filesystem,
controller/process recovery and retained-model evidence, not physical host-power
loss. Private filesystem archive SHA256:
`b7af0d9672f11978428456120e9930a16fc67394d67b17019702c39a683f2c83`.
The [filesystem summary and manifest reconciliation](data/2026-09-13-native-arm64/filesystem-summary.jsonc)
provide the checked file totals and scope without exposing private lab paths.

## Pending-I/O retention and remaining scope

The finite control runner observed a real outstanding NVMe IO_CMD and
blk_execute_rq stack with a stable external ACK prefix before each control. It
briefly paused only the exact firmware worker:4.649ms/1.948ms/0.248ms for reset,
unbind and loss respectively. Reset completed all64 writes; unbind ended with11
ACKs and ENODEV; worker loss ended with1 ACK and EINTR. The unchanged receipt
verifier checked64/11/1 acknowledged sectors,0/1/1 uncertain sectors and0/52/62
untouched sectors, plus both canaries. Worker-loss recovery used the retained
NAND without formatting. No particular NAND programming cut point is claimed.

The backing medium was tmpfs. The kernel-deadlock recovery reboot intentionally
lost the old volatile image after evidence capture; subsequent correction tests
used a new image. Process/controller recovery is not host-power-loss durability.
No raw backend was formatted. P01 hardware erase-generation persistence, N01,
RTOS/real-NAND ports, parallel FTL, richer protocol commands and ARM M5 remain
separate limitations. The named native L1 matrix is complete; final publication
checks remain separate from these runtime results and do not retroactively change
the exact source identities of earlier groups.
